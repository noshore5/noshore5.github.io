Mamba vs. GRU: a real matched comparison, and a debunked earlier result

2026-08-25 · architecture ablation, seizure prediction

Two threads converge here. First, a real, protocol-matched six-fold comparison between the GRU and Mamba temporal backends — the head-to-head that the previous Mamba session deliberately hadn't run yet. Second, a correction: the earlier single-fold Mamba result that looked almost too good turns out to have been testing a seizure that doesn't exist.

A result that needed debunking first

The earlier Mamba full-mesh run held out a seizure labeled 1_02_0, and its training curve hit exactly 0.0 validation loss and 100% validation accuracy by epoch 8, holding there through the early-stopping window — a suspicious signature. Checking chb01's own documentation directly settled it: the dataset has exactly seven real seizures, and the recording that run's driver labeled as holding out 1_02_0 has zero documented seizures in it at all. The seizure ID was an artifact of an indexing bug in the smoke-test driver's capped-interictal path, not a real held-out fold. That earlier result should be read as "the code ran and produced output," nothing more.

A separate discovery, run to ground the same day: a second Mamba run on different hardware showed the identical too-perfect signature. Once that pattern showed up twice, the working theory was that it's specific to the smoke-test driver's small, capped train/validation split — not a real problem with Mamba's training path. A full, uncapped run on the real six seizures settled it: the exact-zero pattern never appeared once across any fold. Validation loss curves looked ordinary everywhere. That closes the concern.

Getting the GRU side onto equal footing first

Before Mamba could be compared fairly, the GRU side needed its own fix: an earlier ablation had removed a dead, do-nothing channel encoder from the model, but that fix had only been tested on one fold. This session ran the same encoder-free model across all six real seizures, with a validation split and early stopping, matching the protocol already used elsewhere:

It also sits well below every channel-subset point from an earlier sweep, meaning the "does a smaller live-edge subset actually beat the full mesh" question still isn't cleanly answered — that sweep still needs a rerun with the encoder removed before it's a fair fight.

Mamba wins on the metric that matters most for this task — average precision, by a real margin — and on both false-alarm numbers, at the same overall detection reliability. Broken down by fold, that AP advantage isn't riding on one lucky result: Mamba beats GRU's ranking on five of the six seizures, several by a wide margin, and loses meaningfully on only one. That's a reasonably broad-based win, not noise from a single fold.

The recall and F1 losses tell a narrower story. Almost the entire gap traces to one seizure, where Mamba's recall collapses to 0.100 against GRU's 0.767 — far larger than the difference on any other fold. Mamba's ranking score on that same seizure (AP 0.618) isn't a collapse, just somewhat weaker than GRU's — the combination of a still-reasonable ranking with a catastrophic recall at the default decision threshold points at a calibration or threshold problem on that one fold, not necessarily a model that failed to learn anything there. Worth checking directly before drawing a conclusion either way.

One more thing worth being honest about: an earlier note described one particular seizure as a "persistent miss across every model variant." This comparison broke that claim in one run — GRU still misses it, but Mamba catches it, while missing a different seizure instead. With only six folds on one subject, a pattern that looks architectural can just be which combinations happened to get tried so far. Worth treating both this session's win and its one loss as provisional rather than settled, and rerunning with a different seed before leaning on either as a real finding.

Open items

The channel-subset sweep still needs an encoder-free rerun before k-versus-full-mesh is a genuine same-model comparison. Mamba's recall collapse on its one weak fold hasn't been investigated directly — whether that seizure's underlying features look unusual, or it's a threshold-calibration artifact, is still open. No null-control run exists for either architecture in this specific comparison. And the ~4.6× per-epoch cost is a real, current-scale number, not a smoke-inflated one — closing that gap depends on infrastructure work (a CUDA-kernel-backed build) that hasn't happened yet.
